# Learning: A Field Guide to Fable — Finding Your Unknowns (Thariq / @trq212)

## Gist
心法向长文。核心一句话：**"the map is not the territory"（地图不是疆域）**。你给 Claude 的 prompt / skills / context 是"地图"；真正干活的地方——codebase、真实世界、实际约束——是"疆域"。两者的差距 = **unknowns（未知）**。Fable 5 是第一个"工作质量的瓶颈从模型能力转移到你澄清 unknowns 的能力"的模型。所以 agentic coding 的真正技能，是在实现**之前/之中/之后**反复地发现、减少、并为 unknowns 做规划。文章给了一个 unknowns 的 2×2 矩阵（Rumsfeld 矩阵）+ 一套按阶段划分的技巧工具箱，底层经济学是：**每一次 explainer/brainstorm/interview/prototype/reference，都是在"变贵之前"用很便宜的方式把 unknown 挖出来。**

## Mastery checklist

### 1. The problem — what & why
- [ ] 能用自己的话解释 map / territory / unknowns 三者关系
- [ ] 能说清"为什么是 Fable"——瓶颈从模型能力→人的澄清能力，且为何"提前 plan"还不够（unknowns 会在实现中/后才冒出来）

### 2. The substance — how & why this way
- [ ] 能准确区分 2×2 四象限，尤其 **unknown knowns vs unknown unknowns** 这对最易混的
- [ ] 能解释"reducing/planning for unknowns 是可习得的技能"以及顶尖 coder（Boris/Jarred）为何 unknowns 少但仍假设有 unknowns
- [ ] 能讲清"太具体 vs 太模糊都会失败"，以及为何"给 Claude 你的起点/思路当 thought partner"是解法
- [ ] 能把每个技巧映射到它针对的象限+阶段（Blind Spot Pass / Brainstorm+Prototype / Interview / Reference / Impl Plan / Impl Notes / Pitch / Quiz），而不是死记 8 个

### 3. The so-what
- [ ] 能陈述核心经济学论点（cheap-now vs expensive-later）并用 launch-video 例子走一遍
- [ ] 能提出最强反驳（"这不就是让我好好写需求吗？"/ 瓶颈真在人吗 / 前置开销成本）并给出回应
