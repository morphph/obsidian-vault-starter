# guide-template.md — 常青读者指南骨架 + 写法纪律

> step 5 `mode:guide` 用。这是**读者指南**的形状(读者旅程),不是选题决策文档。
> 产物是**给人读/发布的成品**,不是喂 Gate-1 的决策表。所有研究元话术(核验状态、GA 标注、
> 存疑辨伪、「推断·未实测」)住 `facts.md`,**绝不进这里的正文**。

## 这是什么 · 和 report 的区别

`report-template.md` 是**选题决策文档**:事实轴 + 渠道 Top-N + 末尾建议角度,读者是"决定写什么"的作者。
`guide-template.md` 是**读者指南**:一条从"这是什么"到"我该怎么上手"的读者旅程,读者是"想学会用这东西"的
AI builder。指南本身即交付物——没有角度闸,没有渠道 Top-N,不问"该写哪个角度"。

判断规则:如果读者读完应该**会用这个东西**(而不是**决定写它的哪个角度**),用本模板。

## 骨架(以读者旅程排序,不以功能清单排序)

下面是单篇指南的完整骨架。成对时(`pair:true` 或题量大):**概览篇**取 §头部契约→§1→§2→功能一览(每功能
"是什么+能干嘛+最小例")→给同类工具用户的映射→上手计划;**进阶篇**取 §头部契约(指向概览篇为前置)→
心智模型(一条流水线)→逐主题深配(处方+逐字配置)→端到端工作流→分阶段实施→可复制模板→架构图→检查清单。
两篇互相引用、不重复。

```markdown
# <动词性标题:读者收益导向,不是"X 介绍">
> 版本日期:<YYYY-MM-DD> · 适用对象:<从 audience-profile.md 具体化——读者已经会什么(如"会用
> Claude Code / Cursor / API"),读完这篇能做什么(如"摸清 Codex 全貌并跑通第一个任务")> ·
> 信息基础:<以官方 X 为准,如"OpenAI 官方 learn.chatgpt.com/docs;能力与套餐会变,以文末官方链接为准">

**一句话:** <一句干净的定义句(X 是……),给 AI 摘要抽取用。前置结论。>

## 1. 心智模型 — 这东西是什么系统(不是功能列表)
用 2-4 段完整叙事讲清楚"它是一类什么东西、边界在哪"。避免一上来堆功能。
收一张**需求→入口/工具决策表**(这是硬配额里的决策表之一):

| 需求/工作类型 | 用哪个入口/工具 |
|---|---|
| <场景 A> | <入口/工具 + 一句为什么> |
| … | … |

## 2. 从你已知的 <同类工具> 映射(读者若已会 Claude Code / Cursor / …)
帮读者用已有心智快速接住新工具。两块:

**能力映射表**(硬配额决策表之一):
| 你已知的 <工具> 概念 | 这里对应 | 主要用途 |
|---|---|---|
| <CLAUDE.md> | <AGENTS.md> | <一句用途> |
| … | … | … |

**职责边界清单(排他分配)** — 用"一次性要求写 A / 长期规范写 B / 重复流程做成 C"式句子,
把容易混的东西各归各位:
- 当前任务的一次性要求 → 写在 prompt。
- 项目长期规范 → 写进 <长期指令文件>。
- 重复的多步骤方法 → 做成 <Skill>。
- 机械的安全拦截/生命周期动作 → 用 <Hook / Rule>。
- 可独立并行的工作 → 交给 <Subagents>。
（每条都是一句能独立成立的判断句。）

## 3..N 主题节(按学习顺序排,不按功能清单顺序)
每个主题**固定节奏**,四拍:
### <主题名>
**是什么:** 一句定义 + 一两句展开(完整句,非括号堆叠)。
**什么时候用:** 触发条件/适用场景,敢下判断。
**最小可复制示例:** 一段能直接抄的命令 / 配置 / prompt(标语言的代码块)。
**处方收尾(必须):**
- ✅ 建议:<该怎么做>
- ⛔ 不要:<别怎么做>
- 判断规则:<"如果…就…否则…"式的一句可执行规则>

> [!tip] <把这一主题最要命的确切默认值 / 精确 gotcha 放这里>
> 例:某键默认值 = X;某调度用 RRULE 不是 cron。**(差异化武器:这类精确事实是我们相对
> 第三方指南的优势,必须织进对应节;但核验过程只留 facts.md。)**

概念易混处插**"不要混淆"辨析块**(排他定位,硬配额之外的加分项,易混主题必加):
> **不要混淆:**
> - "所有修改都必须 typecheck" 属于 <AGENTS.md>;
> - "完成一次版本发布" 属于 <Skill>;
> - "禁止危险命令" 属于 <Rule>;
> - "停止前跑验证" 属于 <Hook>。

## § 端到端工作流(至少一条完整闭环)
给一条从头到尾的闭环 + 一个具体场景:**理解 → 探索 → 计划 → 实施 → 验证 → review → 修复 → 再验证**。
配一段真实感的场景叙事(不是抽象步骤),让读者看到"一次完整的活长什么样"。

## § 分阶段上手/实施计划(硬配额:必有一个)
七天计划(概览/上手篇)或 Phase 1-N(进阶/落地篇)。**每阶段有明确动作 + 验收标准**:
### 第 1 天 / Phase 1:<主题>
- 动作:<具体做什么>
- 验收:<做到什么算过关>
（切忌"了解一下 X"这类无法验收的动作。）

## § 可复制模板(硬配额:≥2 个,拿来即用)
把读者最常用的东西做成能直接抄的模板。例:
- **日常任务 prompt 模板**(Goal / Context / Constraints / Done when 四段式)。
- **长期指令文件示例**(如 AGENTS.md 全文)。
- **无人值守 prompt 模板 / 配置示例 / 数据库 schema / 审批消息格式**(视题材)。
每个模板用代码块,注释说明可改的槽位。

## § 检查清单(硬配额:必有一个,分类勾选框)
按维度分组的 `- [ ]` 清单,让读者上线/交付前逐条勾。例:
### <维度 A,如"身份与网络">
- [ ] <可勾选的具体项>
### <维度 B,如"Agent 边界">
- [ ] …

## § 官方资料索引(末尾集中列)
把正文引到的官方链接集中列在文末,一处一行:
- [<页名>](<官方 URL>)
- …

## 更新记录(常青维护机制,必留)
| 日期 | 变更 | 官方来源 |
|---|---|---|
| <YYYY-MM-DD> | <这次改了什么> | <官方域名/页> |
```

进阶篇/复杂题材另可加(硬配额之外的加分项,进阶题材建议加):
- **架构图(ASCII)** — 把系统组件/数据流画成 ASCII 图(进阶题材**必加**一张)。
- **风险分级表** — | 风险 | 示例 | 建议 |(如动作分级:低/中/高/极高)。
- **状态机** — 任务/流程的状态流转(如 `queued → running → …`)。
- **上线检查表** — 比普通检查清单更细的 go-live gate。

## 写法纪律(硬性要求 — 写完逐条自查,不达标就修到达标)

1. **每节回答"那我该怎么做"**:主题节必须处方式收尾(建议 / 不要 / 判断规则),敢下判断。
   只描述"是什么"而不给"该怎么做"的节 = 不合格。
2. **硬性结构配额(全篇最低线)**:
   - **≥3 张决策表**(需求→入口表、能力映射表、风险分级/选择表 都算)。
   - **≥2 个可复制模板**(prompt 模板、配置/文件全文示例、schema、审批消息 等)。
   - **1 个分阶段计划**(七天 或 Phase 1-N,每阶段有动作 + 验收)。
   - **1 个检查清单**(分类勾选框)。
   - **末尾官方资料索引**(集中列)。
   - **进阶题材另加 ≥1 张架构图(ASCII)**。
3. **完整句叙事,段落 2-6 句。禁笔记压缩体**:不用括号堆叠(如"(A/B/C,默认 X;见下)")、
   不用箭头链当正文(`A → B → C` 只允许出现在流水线/流程图/状态机,不当句子)、不用密集黑体行话堆行。
   报告体("**开关(默认已开)**:`flag=true`,暴露 `a`/`b`/`c` 工具")要改写成读者句
   ("并行能力默认已开,你不用额外打开它;它对外暴露 spawn / send / resume 等几个工具,用来手动管子 agent。")。
4. **禁研究元话术进正文**:「推断·未实测」、✅/⚠️/❌ 核验状态、"官方未标 GA""第三方称…存疑"
   "已过时/我们更新了"——**全部留 `facts.md`**。正文只写已核验结论。拿不准的事实:要么不写,
   要么写成**有实质内容**的 `> [!warning]` callout(说清边界与不确定性,而不是贴个核验标记)。
5. **差异化武器要织入正文**:确切默认值、版本/弃用状态、精确 gotcha——以 `> [!tip]` /
   `> [!warning]` callout 出现在**对应主题节内**(不是堆在文末)。这是 Codex 范文没有、而我们必须
   保留的优势。核验它们的过程留 facts.md;结论进正文。
6. **篇幅目标**:单篇 18-30KB;成对时概览篇 15-25KB、进阶篇 18-30KB。低于下限通常意味着处方/示例/
   模板不够;高于上限就拆成对篇或砍重复。
7. **双语习惯(照仓库惯例 + audience-profile.md)**:中文为主体叙述;英文只在两处——(a) 概念原名
   (中文译名后括注,如"子智能体(subagents)"),(b) 关键原文引语。**不要整段中文再翻成英文重复。**
   代码/配置/命令保持原文。
8. **GEO/AEO(照 audience-profile.md)**:核心概念给干净定义句;段落前置结论(倒金字塔);
   善用小标题/表/callout 让每段能被独立抽取;关键 claim 带官方出处链接(链接放正文或文末索引)。

- [ ] §1 是心智模型(系统是什么),不是功能罗列。
- [ ] 每个主题节都有处方收尾(建议/不要/判断规则)。
- [ ] ≥3 决策表 · ≥2 可复制模板 · 1 分阶段计划(有验收) · 1 检查清单 · 官方索引。
- [ ] 进阶题材有 ≥1 ASCII 架构图。
- [ ] 全篇无研究元话术(核验状态/推断未实测/GA存疑/"已过时")——都在 facts.md。
