# 精要提炼（essence extraction, canonical）

> `/ingest` step 3 **PDF / YouTube 视频类**源的结构（2026-07-15 作者拍板 + deep-research 定型）。
> 与博文不同:PDF/视频往往长、稀、有填充,**不做全文翻译,做提炼**——把核心论点、框架、关键数据、金句、可执行要点抽出来。
> 博文 / 文章 / 长推文**不走这个**,走 `references/structured-close-reading.md`(全文自然翻译)。

**目的**：把一份长/稀的源(论文、报告、书、演讲、教程视频)提炼成**信息密度高、可直接吸收**的中文精要。读者读完精要,应该拿到这份源里所有值得学的东西——而不必看完全部原文。

## 方法论（有研究支撑,直接决定质量,务必遵守）

- **为覆盖度而工程化(第一要务)**：LLM 总结长文的头号失败模式是**漏**(salient 内容被省略),远多于瞎编。所以提炼时**先求全、再求精**——宁可多列一条,不要漏掉一个真正的要点。
- **主动盯住中段(lost-in-the-middle)**：模型天然把开头结尾覆盖好、忽略中段。**刻意检查文档/转录的中间部分**有没有被跳过——这是覆盖度最容易塌的地方。
- **中等密度,不是越密越好**：目标是人类偏好的"甜点密度"——每个要点讲清楚(是什么/为什么重要),不要压成一串无法解读的关键词。信息全、但仍可读。
- **单遍、整篇进上下文,不要 map-reduce**：分块合并(hierarchical / map-reduce)会**伤保真**。把整份源(PDF 全文 / 完整转录)一次读进上下文,单遍提炼,靠结构化的 prompt 引导注意力。Opus 1M 上下文足够;只有源实在超长才分块,且分块时把摘出的原句当**佐证**而非替代。
- **提炼式,不是浅层摘要**：抓的是"claims + examples + numbers + quotes + actionable takeaways",不是三行概括。
- **忠于源,不脑补**：转录可能没标点/说错词、PDF 可能有 OCR 噪声——**不确定就标注,不要替它编**。数字、专有名词逐字保留。

## 结构

外层由 step 4 包成 `## 精要` section。内部：

## 0. 元信息头

```
# 精要：{原文标题}
**作者/讲者**：{姓名 + 一句话身份/stake}
**来源**：{平台/出版方} · {日期} · [原文/视频]({URL})
**篇幅**：{PDF 约 N 页 / 视频约 M 分钟} · **精要预读时长**：约 {K} 分钟
**一句话主旨**：{一句话说清这份源讲什么、核心主张是什么}
```

`**一句话主旨**：` **逐字用这个字段名**——WF1 gate packet 直接提取当 Hook,格式错了下游就断。

## 1. 核心论点（Thesis）
2-3 句中文说清整份源的核心主张。格式建议:"作者/讲者主张 X,因为 Y,所以 Z。"这是整份源的压缩包。

## 2. 内容骨架
这份源分几大块、按什么逻辑推进?列出骨架(章节/段落主题 or 视频分段)。**这一步同时是覆盖度自检**——骨架列全了,后面各节才不会漏掉中段。

## 3. 关键概念 & 框架 / 心智模型
每个值得记的概念/框架用一小段(不是一行带过):
> **概念中文名 (English Original)**
> - **是什么**:精确定义
> - **为什么重要**:在整个 thesis 里的角色
> - **怎么用 / 何时用**:适用场景;有决策规则/流程就写出来 + 一个具体例子

## 4. 关键数据与事实
所有量化数据、benchmark、case study 结果、关键事实——**逐字保留数字**,每条注明它支撑哪个观点。这些是可信度核心,也是日后引用的弹药。

## 5. 金句
3-7 条最有冲击力的原话(EN 原文 + 中译)。视频转录里的口语金句同样算。

## 6. 可执行要点（Takeaways）
作者/讲者明确的"how to do"→ 给步骤/清单。只有方法论没给步骤的,你帮他翻成可执行步骤;只是案例的,反推出可复用 pattern。

## 7. 收尾

```
---
## 精要收尾
- **一句话总结**：{可发推级别的压缩}
- **与 vault 的连接**：{[[wikilink]] ×2-4,一句话说明关联；先扫 wiki/index.md 确认页面存在}
- **视频适配自评**：{适合/不适合做白板讲解视频 + 一句话理由}
- **覆盖度自检**：{一句话确认——骨架各段(尤其中段)是否都在上面各节体现了;有意略过的说明为什么}
```

（不是每份源都需要全部 section——不适用的明确写"无",让用户知道你想过了。）

## 源类型专项提醒

- **YouTube 视频**：正文是**字幕/转录**(获取见 SKILL.md step 1)。转录常无标点、无讲者标签、自动字幕有错词——提炼时容忍噪声但不脑补;能对上 slides/演示的用 §3 概念讲清楚。时间戳可选保留(便于回看)。
- **PDF**：用 `Read` 工具**读全**(长 PDF 分页读,别只读前几页——中段最容易漏)。表格/图:结构照搬或一句话描述。扫描件/图重的 PDF:`Read` 的视觉能力直接读;实在读不动再向用户说明。
