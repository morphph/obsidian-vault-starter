# 原文结构精读（structured close reading, canonical）

> `/ingest` step 3 的**默认结构**（作者 2026-07-07 拍板，替代 12 段 study guide 作为学习线默认；用户明确要求 study guide 时仍用 `study-guide-12.md`）。
> 目标是**读完精读 ≈ 读完原文**：作者读中文更快，精读是他学习英文原文的主通道，同时是下游视频 script 口语化的直接底稿。

**目的**：把英文原文以中文精读的形式完整、忠实地交给用户。不重组、不再创作、不塞解读框架——原文说什么、按什么顺序说，精读就按什么顺序讲什么。

**核心原则**：
- **贴原文结构**：严格按原文章节/小节顺序走，章节标题保留英文原题 + 中译。原文没有的结构不要发明；原文的论证链一步不跳。
- **压缩翻译密度**：介于逐句翻译与摘要之间——每段原文对应一段中文精读，保留论证与例子，压掉纯修辞与重复。宁可偏长，不可漏论证。**不逐句直译**（避免翻译腔），用自然中文重述。
- **术语留英文原名**：概念首次出现给「中文译名 (English Original)」，之后可只用英文原名。不要为翻译而翻译（prompt caching 就是 prompt caching）。
- **关键引语 EN + 中译**：最有冲击力的原句保留英文原文 + 紧跟中文意译（引语是日后写稿的弹药）。
- **数据逐字保留**：所有数字、基准、百分比逐字照搬（"102 features in 7 days" 不许变成「一周上百个功能」）。
- **解读克制**：个人评论/联想只允许出现在收尾的「与 vault 的连接」和「视频适配自评」，正文里不夹私货——正文的忠诚对象是原文。

**完整结构**：

---

## 0. 元信息头

```
# 精读：{原文标题}
**作者**：{姓名 + 一句话身份/stake}
**来源**：{平台} · {日期} · [原文]({URL})
**原文字数**：约 {N} words · **精读预读时长**：约 {M} 分钟
**一句话主旨**：{一句话说清这篇讲什么、核心主张是什么}
```

「一句话主旨」会被 WF1 gate packet 直接提取当 Hook，认真写。

## 1. 正文精读（主体）

按原文章节顺序，每章：

```
## {章节序号}. {英文原题}（{中译}）
{该章精读：压缩翻译密度的中文重述，含该章的论证、例子、数据}
```

- 原文无小标题的（如长推文/散文体），按其自然段落主题切块，块题用中文概括并注明「（原文无小标题，此为段落主题）」。
- 代码块/表格/清单：结构照搬，注释性文字中译。
- 原文配图：保留图片引用或用一句话描述图的内容（「图：…」）。

## 2. 收尾（正文之后，明确分隔）

```
---
## 精读收尾
- **一句话总结**：{可发推级别的压缩}
- **关键引语**：{3-5 条 EN + 中译，正文已出现的可汇总于此}
- **与 vault 的连接**：{[[wikilink]] ×2-4，一句话说明关联；先扫 wiki/index.md 确认页面存在}
- **视频适配自评**：{适合/不适合做白板讲解视频 + 一句话理由（概念结构是否可图示、论证是否有讲解张力）}
```

---

## 与图示的配合（S2/S3 起生效）

精读若配了白板图示（excalidraw-diagram skill 产出），PNG 嵌在**最相关章节精读之后**：`![[{slug}-diagram.png]]`。图示步骤应对应原文的论证展开顺序（图是原文结构的空间化，不是另一套解读）。
